Módulo 2 — Lección 07 — Actividad en clases

Tu Carta Coleccionable de Desarrollador en GitHub Pages

Vas a diseñar tu propia carta estilo "trading card" de un universo de programadores. Luego la subirás a un repositorio nuevo en GitHub y la publicarás como un sitio en vivo con GitHub Pages para compartirla con quien quieras.

Contexto

Imagina que existe un juego de cartas coleccionables donde cada carta representa a un desarrollador. Tu misión es crear tu carta personal: un nombre de batalla, una clase (frontend, backend, fullstack), una rareza, estadísticas en tecnologías, una habilidad especial y un dato curioso. Todo en una página web hecha desde cero con HTML, CSS y un toque de JavaScript.

Al final del ejercicio tu carta estará publicada en una URL del tipo https://<tu-usuario>.github.io/mi-carta-dev/ que podrás compartir con tus compañeros, en redes sociales o en tu currículum.

Antes de empezar
  • Tener Git instalado y configurado con tu nombre y correo.
  • Tener cuenta de GitHub activa.
  • Tener Visual Studio Code instalado.
  • Tener un Personal Access Token de GitHub a mano (Settings → Developer settings → Tokens), o SSH configurado.
Habilidades que se evaluarán
  • Estructura HTML semántica y estilizada con CSS.
  • Interacción mínima con JavaScript usando jQuery.
  • Inicialización de un repositorio Git local.
  • Creación de un repositorio remoto en GitHub.
  • Conexión de local con remoto y primer push.
  • Publicación de un sitio estático con GitHub Pages.
01
Crea la estructura del proyecto

Desde Visual Studio Code, crea una nueva carpeta llamada mi-carta-dev en tu directorio de trabajo y ábrela.

Dentro, crea los siguientes archivos: index.html, estilos.css y script.js.

Pasos en Visual Studio Code
  1. File → Open Folder… y elige (o crea) la carpeta mi-carta-dev.
  2. En el explorador, clic derecho dentro de la carpeta → New File → escribe index.html.
  3. Repite para estilos.css y script.js.
Verificación: en el panel lateral de VS Code la carpeta mi-carta-dev muestra los tres archivos.
02
Diseña la estructura HTML de tu carta

En index.html construye una estructura HTML mínima con:

  • <!DOCTYPE html>, etiquetas html, head y body.
  • En el head: meta charset, meta viewport, un title con tu nombre de batalla, la vinculación a estilos.css y la inclusión de jQuery desde CDN (<script src="https://code.jquery.com/jquery-3.7.1.min.js"></script>).
  • En el body, un contenedor con clase carta que incluya:
    • Un encabezado con tu nombre de batalla y tu clase (Frontend, Backend o Fullstack).
    • Una imagen o avatar (puede ser un emoji grande dentro de un <div>, una imagen libre de Unsplash, o un avatar de DiceBear: https://api.dicebear.com/7.x/bottts/svg?seed=tu-nombre).
    • Una sección Estadísticas con al menos 3 tecnologías y un valor de 1 a 100 cada una.
    • Una sección Habilidad especial con un nombre creativo y una descripción de una línea.
    • Una rareza visible (Común, Rara, Épica o Legendaria).
    • Un botón con id btn-activar que diga "Activar habilidad".
  • Al final del body, un <script src="script.js">.

Guarda con Ctrl + S (o Cmd + S).

Verificación: al abrir index.html en el navegador (doble clic), se ven todos los elementos aunque aún sin estilos.
03
Dale estilo: que parezca una carta real

En estilos.css, dale identidad visual a la carta. Como mínimo:

  • Centra la carta en la pantalla (flexbox o grid).
  • Dale a la carta un ancho fijo (por ejemplo 320px), bordes redondeados, sombra y un fondo con degradado.
  • El color del borde debe cambiar según la rareza: dorado para Legendaria, morado para Épica, azul para Rara, gris para Común.
  • Para cada estadística, muestra una barra de progreso usando un div contenedor y un div hijo con ancho en porcentaje.
  • Hover sobre la carta: levántala con transform: translateY(-8px) y aumenta la sombra.
  • Asegura que el botón se vea como botón (padding, cursor pointer, estado hover).
Verificación: al recargar el navegador la carta tiene aspecto de carta de juego, las barras se ven proporcionales y el hover responde.

Si no se te ocurre la paleta, partir de un fondo oscuro (#1a1a2e) con texto claro y un acento dorado (#f4c430) suele funcionar bien.

04
Agrega vida con jQuery

En script.js, usando jQuery, haz que el botón "Activar habilidad" tenga un comportamiento divertido. Recuerda envolver tu código en $(document).ready(function () { ... }); para asegurarte de que el DOM ya está cargado.

Elige al menos dos de estas opciones y déjalas funcionando:

  • Al hacer clic, mostrar un alert con el nombre de tu habilidad especial.
  • Agregar una clase CSS a la carta con .addClass() que cambie su color de fondo o le aplique una animación.
  • Llevar la cuenta de activaciones mostrándola en pantalla con .text() sobre un elemento dedicado.
  • Al pasar el mouse sobre la carta (.hover()), cambiar dinámicamente el texto de la rareza por algo divertido y volverlo al original al salir.
// script.js - estructura jQuery sugerida
$(document).ready(function () {

  // 1. Click en el botón
  $("#btn-activar").click(function () {
    alert("¡Habilidad activada!");
    $(".carta").addClass("activa");
  });

  // 2. Contador de activaciones
  let veces = 0;
  $("#btn-activar").click(function () {
    veces++;
    $("#contador").text("Activada " + veces + " veces");
  });

  // 3. Hover sobre la carta
  $(".carta").hover(
    function () { $(".rareza").text("¡LEGENDARIA!"); },
    function () { $(".rareza").text("Rara"); }
  );

});

Para que la opción del contador funcione, agrega en tu HTML un <span id="contador"></span> dentro de la carta. Para la animación, define la clase .activa en tu CSS con cambios visibles (color, transform, etc.).

Verificación: al hacer clic en el botón ocurre algo visible y consistente con el tema de la carta. Las interacciones con jQuery funcionan sin errores en la consola del navegador.
05
Inicializa el repositorio local

Abre la terminal integrada de VS Code (Terminal → New Terminal) ubicado dentro de la carpeta mi-carta-dev. Inicializa Git, agrega todos los archivos y haz tu primer commit.

# Verificar que estás en la carpeta correcta
pwd

git init
git status

git add --all
git commit -m "feat: version inicial de mi carta de desarrollador"

git log --oneline
Verificación: git log --oneline muestra un commit, y git status queda limpio.
06
Crea el repositorio en GitHub

Entra a github.com con tu cuenta y crea un nuevo repositorio vacío. No lo inicialices con README, .gitignore ni licencia (los crearás tú).

Pasos en la interfaz de GitHub
  1. Botón verde New (o ícono + → New repository arriba a la derecha).
  2. Repository name: mi-carta-dev
  3. Description: "Mi carta coleccionable de desarrollador"
  4. Visibilidad: Public (necesario para usar GitHub Pages gratis).
  5. NO marques Add a README file, ni .gitignore, ni license.
  6. Botón Create repository.

Copia la URL del repo que aparece en la página siguiente (formato HTTPS): se ve como https://github.com/<tu-usuario>/mi-carta-dev.git.

Verificación: tienes una página de repositorio nuevo en GitHub con instrucciones de "push an existing repository from the command line" y la URL copiada.
07
Conecta tu repo local con GitHub y sube

Vuelve a la terminal de VS Code. Conecta tu repositorio local con el remoto que acabas de crear, asegúrate de que tu rama se llame main y haz el primer push.

# Conectar remoto (reemplaza por TU URL)
git remote add origin https://github.com/<tu-usuario>/mi-carta-dev.git

# Verificar
git remote -v

# Asegurar nombre de rama main
git branch -M main

# Primer push (vincula la rama local con la remota)
git push -u origin main

Si Git te pide credenciales, ingresa tu usuario de GitHub y, como contraseña, tu Personal Access Token.

Verificación: al recargar tu repositorio en github.com aparecen los tres archivos (index.html, estilos.css, script.js) y tu commit en el historial.
08
Activa GitHub Pages

Publica tu carta como un sitio en vivo usando GitHub Pages.

Pasos en la interfaz de GitHub
  1. Dentro de tu repo mi-carta-dev, ve a la pestaña Settings.
  2. En el menú lateral izquierdo, sección Code and automation, haz clic en Pages.
  3. En Source elige Deploy from a branch.
  4. En Branch, selecciona main y carpeta / (root).
  5. Botón Save.
  6. Espera entre 30 segundos y 2 minutos. Recarga la página de Pages: aparecerá un cuadro verde con tu URL pública: https://<tu-usuario>.github.io/mi-carta-dev/.
Verificación: al abrir la URL pública en una pestaña nueva del navegador, tu carta se muestra exactamente como en local y el botón de habilidad funciona.

Si ves una página 404, espera un minuto más y recarga. También revisa que index.html esté en la raíz del repo (no dentro de subcarpetas).

09
Itera y publica un cambio

Ya tienes el flujo completo. Ahora demuestra que sabes mantenerlo: vuelve a VS Code, modifica algo visible de tu carta (cambia un valor de estadística, agrega una nueva o cambia el color de fondo). Guarda, commitea y empuja al remoto.

# Edita archivos en VS Code y guarda

git status
git add --all
git commit -m "feat: ajusta estadisticas y color de la carta"
git push

Espera unos segundos y recarga la URL pública: tus cambios aparecen en vivo.

Verificación: el sitio publicado refleja los cambios que acabas de hacer, sin necesidad de reactivar GitHub Pages.
10
Comparte tu carta

Copia la URL pública de tu sitio (https://<tu-usuario>.github.io/mi-carta-dev/) y compártela en el canal del curso. Revisa al menos 2 cartas de tus compañeros y deja un comentario sobre cuál habilidad te gustó más.

Verificación: tu URL está publicada en el canal del curso y has comentado al menos 2 cartas de compañeros.
