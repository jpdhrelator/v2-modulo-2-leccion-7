Módulo 2 — Lección 07 — Actividad en clases

Tu primer Pull Request en GitHub

Vas a colaborar sobre el repositorio del curso. Crearás tu propia rama, subirás un cambio y abrirás un Pull Request para que el profesor lo revise y lo fusione.

Contexto

El profesor mantiene un repositorio del curso al cual cada uno de ustedes debe contribuir agregando un archivo Markdown con su presentación personal. Vas a trabajar como colaborador del repositorio: clonas, creas tu propia rama, haces tu commit, lo subes y abres un Pull Request hacia main. Cuando el profesor lo apruebe, tu archivo quedará para siempre en la historia del curso.

Antes de empezar
  • Tener una cuenta de GitHub activa.
  • Estar agregado por el profesor como colaborador del repositorio del curso (revisa la invitación en tu correo y acéptala).
  • Tener Git instalado y configurado con tu nombre y correo (el mismo de GitHub).
  • URL del repositorio del curso: https://github.com/jpdhrelator/cv2-modulo-2-leccion-7-alumnos.git (te la entregará el profesor).
Habilidades que se evaluarán
  • Clonar un repositorio remoto.
  • Crear y posicionarse en una rama con nombre descriptivo.
  • Commit con mensaje claro siguiendo buenas prácticas.
  • Push de la rama al repositorio remoto.
  • Apertura, descripción y seguimiento de un Pull Request.
  • Respuesta a comentarios de revisión.
  • Sincronización de la rama local tras el merge.
01
Acepta la invitación y clona el repositorio

Revisa tu correo o tus notificaciones en GitHub y acepta la invitación que el profesor te envió para ser colaborador del repositorio del curso.

Una vez aceptada, abre tu terminal, ubícate en una carpeta de trabajo (por ejemplo ~/cursos) y clona el repositorio del profesor en tu máquina.

# Ubicarse en la carpeta donde trabajar
mkdir -p ~/cursos
cd ~/cursos

# Clonar el repositorio del curso
git clone https://github.com/jpdhrelator/cv2-modulo-2-leccion-7-alumnos.git
cd cv2-modulo-2-leccion-7-alumnos

# Verificar el remoto
git remote -v
ls
Verificación: al listar el remoto debe aparecer origin apuntando al repo del profesor, y al listar el contenido debe verse la carpeta alumnos/.
02
Asegúrate de partir desde main actualizado

Posiciónate en la rama main y trae los últimos cambios desde el remoto. Esto es clave: nunca crees una rama desde una versión vieja.

git checkout main
git pull origin main
git log --oneline -5
Verificación: el mensaje de git pull debe decir "Already up to date" o haberte traído nuevos commits sin conflictos.
03
Crea tu rama personal

Crea una nueva rama usando una convención de nombres clara. Para esta actividad, el formato será alumno/<tu-nombre> (todo en minúsculas, sin tildes y separando palabras con guiones). Por ejemplo: alumno/juan-perez.

Posiciónate en esa rama.

git checkout -b alumno/<tu-nombre>

# Confirmar en qué rama estás
git branch
Verificación: el comando git branch debe mostrar tu rama nueva marcada con un asterisco.
04
Crea tu archivo Markdown de presentación

Dentro de la carpeta alumnos/ crea un archivo con tu nombre, en formato alumnos/<tu-nombre>.md (mismo nombre que usaste para la rama).

El archivo debe contener al menos:

  • Un título principal con tu nombre completo.
  • Una sección Sobre mí con 2 o 3 líneas de presentación.
  • Una sección Stack que estoy aprendiendo en formato de lista de viñetas.
  • Una sección Contacto con un enlace a tu perfil de GitHub.
Pasos en Visual Studio Code
  1. Abre la carpeta del repositorio en VS Code (File → Open Folder...).
  2. En el panel del explorador haz clic derecho sobre la carpeta alumnos/ → New File.
  3. Nombra el archivo tu-nombre.md (mismo nombre que tu rama, en minúsculas y con guiones).
  4. Escribe el contenido siguiendo la estructura Markdown sugerida abajo.
  5. Guarda con Ctrl + S (o Cmd + S en Mac).
# Estructura Markdown sugerida para el contenido del archivo:
#   # Nombre Completo
#   ## Sobre mí
#   Texto breve...
#   ## Stack
#   - HTML
#   - CSS
#   - JavaScript
#   ## Contacto
#   [Mi GitHub](https://github.com/tu-usuario)
Verificación: el archivo existe dentro de alumnos/ y al previsualizarlo en VS Code (clic derecho → Open Preview) se ve con sus secciones bien formateadas.
05
Commitea tu cambio

Agrega el nuevo archivo al área de preparación y haz un único commit con un mensaje descriptivo siguiendo el formato docs: agrega presentación de <tu-nombre>.

git status
git add alumnos/<tu-nombre>.md
git status
git commit -m "docs: agrega presentacion de <tu-nombre>"
git log --oneline -3
Verificación: git status queda limpio después del commit y el historial muestra tu commit como el más reciente en tu rama.
06
Sube tu rama al repositorio remoto

Envía tu rama personal al repositorio del profesor. Es la primera vez que la subes, así que debes vincular la rama local con el remoto.

git push -u origin alumno/<tu-nombre>

Si Git te pide credenciales, ingresa tu usuario de GitHub. Como contraseña no uses tu password de GitHub — usa un Personal Access Token generado desde GitHub → Settings → Developer settings → Tokens, o configura SSH.

Verificación: al entrar al repositorio del profesor en GitHub y abrir el desplegable de ramas, debe aparecer tu rama alumno/<tu-nombre>.
07
Abre el Pull Request

Entra al repositorio del curso en GitHub y abre un Pull Request desde tu rama hacia main.

Pasos en la interfaz de GitHub
  1. En la página principal del repo verás un banner amarillo que dice "alumno/tu-nombre had recent pushes" con un botón Compare & pull request. Haz clic.
  2. Si no aparece, ve a la pestaña Pull requests → botón New pull request. En base elige main, en compare elige tu rama.
  3. Escribe un título claro: docs: agrega presentación de <tu-nombre>
  4. En la descripción incluye:
    • Qué archivo agregaste.
    • Una línea sobre ti.
    • Tu usuario de GitHub.
  5. En el panel derecho, en Reviewers, asigna al profesor.
  6. Haz clic en Create pull request.
Verificación: en la pestaña Pull requests del repo aparece tu PR abierto con tu título, descripción y el profesor asignado como reviewer.
08
Atiende los comentarios de revisión

El profesor revisará tu PR y dejará comentarios. Lee cada uno con calma y aplica los cambios solicitados en local.

Para cada cambio: edita el archivo, commitea con un mensaje claro (por ejemplo fix: ajusta titulo segun revision) y vuelve a subir tu rama. El PR se actualiza automáticamente con tu nuevo commit.

# Asegurate de estar en tu rama
git branch

# Editar el archivo segun los comentarios
git add alumnos/<tu-nombre>.md
git commit -m "fix: aplica cambios solicitados en la revision"
git push

Cuando hayas resuelto un comentario, vuelve al PR en GitHub y marca el comentario como Resolved.

Verificación: en el PR aparece un nuevo commit con tus correcciones, los comentarios atendidos están marcados como resueltos y el estado del PR pasa a permitir el merge.
09
Confirma el merge y sincroniza tu local

Cuando el profesor apruebe el PR, será él quien haga el merge. Una vez fusionado, tu trabajo está oficialmente en main.

Para que tu copia local quede al día, vuelve a tu rama principal y trae los cambios. Luego elimina tu rama local y la rama del remoto (ya no la necesitas).

git checkout main
git pull origin main

# Confirmar que tu archivo aparece en main
ls alumnos/

# Eliminar tu rama local
git branch -d alumno/<tu-nombre>

# Eliminar tu rama en el remoto
git push origin --delete alumno/<tu-nombre>
Verificación: tu archivo alumnos/<tu-nombre>.md está visible en main tanto en local como en github.com, y tu rama personal ya no aparece en el listado del repositorio.

Si por error la rama local tiene cambios sin pushear, Git no te dejará eliminarla con -d. Revisa esos cambios antes de forzar la eliminación.
